agent-sidecar {{ .Chart.AppVersion }} is installed in namespace {{ .Release.Namespace }}.

1. Wait for the control plane (embassy-ca creates the CA, the serving certificate and the webhooks'
   caBundle; embassy starts once Secret embassy-tls exists):
     kubectl -n {{ .Release.Namespace }} rollout status deployment/embassy-ca deployment/embassy

2. Enable injection for a namespace and give each service a Charter:
     kubectl label namespace <ns> agentsc.io/injection=enabled
     agentsc charter to-cr <service>.charter.yaml | kubectl apply -f -
   Pods get the agentsc-runtime and agentscd sidecars when they carry the label
   agentsc.io/inject: "true" and the annotations agentsc.io/service: <service> and
   agentsc.io/app-port: "<port>". The pod's service account must be named like the service or be
   listed in the charter's service.service_accounts.
{{- if not (include "agent-sidecar.sidecarImageDigests" . | fromJsonArray) }}

WARNING: the sidecar image allow-list is OFF (no images.agentscd.digest, no
injection.allowedImageDigests): any image may run as the sidecar and get certificates. This is
for development builds only; in production pin images.agentscd.digest (README: Sidecar integrity).
{{- end }}

3. Open the console:
     kubectl -n {{ .Release.Namespace }} port-forward svc/embassy 8080:8080
     open http://localhost:8080
{{- if not .Values.auth.tokens }}
   No API token is configured yet. Create one and add its entry to auth.tokens (SHA-256 only):
     embassy token create --name <you> --role admin --payloads
{{- end }}

Writing Charter resources is equivalent to the agentsc admin role for that service; grant the
agentsc-charter-edit ClusterRole accordingly.
