# 10. A2A at the edge: an A2A server per sidecar and `type: a2a` tools

Status: implemented
Date: 2026-11-08

## Context

Agents in attache call each other over the mesh (gRPC over mTLS), which only mesh members can
use. A2A 1.0 (Agentic AI Foundation) is the open protocol for agents of different
organisations: agent cards, JSON-RPC `SendMessage`, and tasks with states, among them
`TASK_STATE_INPUT_REQUIRED`. attache's agents already ask their callers questions (`ask_caller`,
CONTRACT.md §4.1), and those questions map onto that state. The full design is
[docs/design/a2a.md](../design/a2a.md).

## Decision

1. **Schema level 10**: `agents[].a2a` (`description`, `skills`) serves an agent over A2A;
   `a2a:<name>` identities in `authz.callers` name its callers; `type: a2a` tools call remote
   agents (`url`, optional `credential` or `delegation`, fixed parameters `input`, `context`,
   `task_id`).
2. **An A2A server per sidecar, off by default** (`--a2a-addr`, `--a2a-public-url`,
   `--a2a-callers-dir`): cards at `/a2a/<agent>/.well-known/agent-card.json`, JSON-RPC at
   `/a2a/<agent>`, protocol 1.0 only, plain HTTP behind an ingress that terminates TLS.
3. **Callers are identities with static bearer tokens**, one Secret file per caller, read on
   every request; `authz.callers` decides which agents each reaches.
4. **A2A input is untrusted**: the run starts with the `untrusted` label, and a served agent must
   have a `taint` block.
5. **`SendMessage` is one invocation**; questions become an input-required task, and the reply
   to that task invokes the agent again with the first input and `context.answers`. Tasks are in
   memory for an hour. No streaming, push or `ListTasks`.
6. **`type: a2a` tools are egress** (default `untrusted` / `write`), sent by the sidecar like MCP
   tools, polling a working task until the call's run budget ends; an input-required answer
   names the `task_id` for the model to answer with another call.
7. **One RPC shape for argument-only tools**: `InvokeMcp` and the new `InvokeA2a` take
   `ToolArgumentsRequest` and return `ToolTextResponse` (renamed from `ToolMcpRequest` and
   `McpResponse`, which no release shipped), and `--mcp-secrets-dir` became
   `--tool-secrets-dir` for both tool types.
8. **Records**: `a2a_call` (callee `a2a <origin>`), spans `invoke_agent <host>`; adding or
   removing an `a2a` block and a new `a2a` origin need admin.

## Consequences

- An outside agent reaches an attache agent only through the same authz, budgets, guardrails,
  taint and audit as any caller, and its text cannot make the agent write without the taint
  rules' consent.
- Tasks do not survive a restart, and a caller that waits for a long run holds its HTTP request
  open; durable and streamed tasks are later work.
- A2A callers need a token each, distributed out of band; OAuth and mTLS are later work.
- Cards are unsigned, and an `a2a` tool trusts the endpoint the charter names rather than a
  card it fetched.

## Alternatives

- **A2A on the mesh too.** The mesh already has identity, mTLS and taint propagation that A2A
  does not carry; replacing it would lose them for no gain inside the cluster.
- **A central A2A gateway.** It could not apply per-run taint, and would add a hop outside the
  sidecar's records. A gateway in front (for TLS, routing and rate limits) still works.
- **Mapping questions to `TASK_STATE_INPUT_REQUIRED` with a runtime that keeps state.** The
  runtime is stateless by design; replaying the input with the answers keeps each run one policy
  decision.
- **Fetching the remote card for the tool's description.** The remote party would write the
  prompt, as MCP servers would without pins.
